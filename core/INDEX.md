# 📖 Enterprise RAG Markdown Core (`core/`)

The `core/` directory contains the project's canonical Markdown core, defining the system rules, architecture, database DDL schema, software contracts and the testing / CI-CD procedures.

---

## 🗂️ Navigation and structure of the core files

1. [**`soul.md`**](./soul.md) — the assistant's mission, system rules, communication style, context isolation from Indirect Prompt Injection (`<untrusted_doc_context>`), generation prompt templates, Query Condensation, Intent Router and LLM-as-a-Judge.
2. [**`architecture.md`**](./architecture.md) — a detailed diagram of the system layers, the hybrid model (SaaS Cloud + Protected On-Premise Box), the request lifecycle (Query Flow), the background data ingestion pipeline (Ingestion Flow with debounce), S3 integration and the fault-tolerance matrix (Resilience Matrix).
3. [**`licensing_and_distribution.md`**](./licensing_and_distribution.md) — cryptographic license protection (Ed25519), building the protected core (Cython/PyArmor), delivering boxes via a private Docker Registry, Heartbeat telemetry and the embeddable Web widget.
4. [**`storage_schema.md`**](./storage_schema.md) — PostgreSQL 15+ / pgvector DDL migration (Supabase is one hosting option), table schemas (`tenants`, `licenses`, `documents`, `parent_chunks` with a denormalized `access_level`, `child_chunks`, `conversations`, `messages`, `storage_credentials`), access-control tables (`groups`, `user_groups`, `collections`, `document_collections`, `document_acl` — behind the `enterprise_acl` flag), HNSW and `sparsevec` indexes, the `hybrid_search_rrf` SQL function as an internal detail of `PgVectorStore`, the re-classification contract (`cascade_access_level` + backfill), the RLS + SQLAlchemy contract (`SET LOCAL app.current_tenant_id` + `app.user_access_level`) and additive-only migrations.
5. [**`modules_spec.md`**](./modules_spec.md) — strict Python contracts and Pydantic V2 schemas (`LicensePayload`, `TenantContext`, `RawDocument`, `ParentChunk`, `ChildChunk`, `RetrievalCandidate`, `RAGResponse`), access-control models (`Group`, `Collection`, `DocumentAclEntry`, `AccessDecision`, `UserContext` with `group_ids`/`external_subject`), channel and branding contracts (`ChannelType`, `ChannelCapabilities`, `ChannelEvent`/`ChannelEventType`/`AttachmentRef`, `BrandingConfig`/`WidgetBranding`/`TelegramBranding`, `WebWidgetSession*` with `auth_mode`), the base interface abstractions (`BaseLicenseValidator`, `BasePolicyEvaluator` — the single access-decision point, `BaseChannel`, `BaseEmbedder`, `BaseReranker`, `BaseLLM`, `BaseDocumentSource`) and the Taskiq task signatures.
6. [**`eval_and_ops.md`**](./eval_and_ops.md) — the RAGAS quality-evaluation methodology on a verification golden dataset, multi-tenant self-hosted Langfuse (one project per tenant, read-only Viewer access for the client, provisioning, the trace contract, PII masking), the multi-stage `Dockerfile` configuration, `docker-compose.yml` (admin / widget / worker / langfuse), monorepo tooling (pnpm + uv), Postgres `LISTEN/NOTIFY`, separate rate-limit policies and the GitHub Actions CI/CD pipeline.
7. [**`admin_panel.md`**](./admin_panel.md) — the specification of the private operator contour (Admin SPA + FastAPI `/api/v1/admin/*`): a single build for both `deployment_mode` values, `fastapi-users` authentication (HTTP-only cookie + CSRF + TOTP 2FA), RBAC (`admin`/`operator`/`viewer`), §5A access management (document re-classification, user CRUD and clearance granting, groups/collections/ACL with an audit of every mutation), separation of the session (`HS256`) and licensing (`Ed25519`) keys, a file manager with live statuses via `LISTEN/NOTIFY`, RAG-chunk visualization, the licensing screen, the observability access block (Langfuse: URL/login, a one-time password reset) and the CLI fallback for air-gapped setups.
8. [**`channels.md`**](./channels.md) — the **single source** for user delivery channels (the end search user): the `ChannelType` registry (`web`/`telegram`/`rest_sse`/`cli`), the canonical `ChannelCapabilities` table, the channel-neutral `ChannelEvent`, the Web-widget handshake (Origin allowlist without wildcard, a short-lived JWT, Shadow DOM), `data-api-url` and the Cloud/Box modes, Telegram white-label (avatar only via BotFather), typed branding (`BrandingConfig`/`WidgetBranding`/`TelegramBranding`) with `config_version`, limits and sanitization rules.
9. [**`vendor_backoffice.md`**](./vendor_backoffice.md) — the specification of the **vendor super-admin contour** (`/api/v1/backoffice/*`), SEPARATE from the tenant admin panel: the `BackofficeRole` roles (`superadmin`/`support`/`finance`/`sales`), the separation of `customer` (legal entity) ↔ `tenant` (installation), the customer catalog, license issuance/revocation/renewal, activation codes, the box registry (`box_deployments`), cross-tenant observability (Langfuse), break-glass impersonation with mandatory auditing and prioritization of delivery waves.
10. [**`license_server.md`**](./license_server.md) — the **server half of licensing** (`BaseLicenseServer`): issuance, revocation, heartbeat and the certificate revocation list (CRL), the signing service / HSM / KMS with an offline Ed25519 key, the `online_subscription`/`airgap_enterprise` profiles, grace/Restricted Mode, key rotation and hardware re-activation.

## 🔒 Core governance

- **Source of truth**: the Markdown core in the `core/` directory is the system's primary contract.
- **Observability is part of the core**: the multi-tenant Langfuse contract (one project per tenant, read-only Viewer access, provisioning, the trace contract) is fixed in `eval_and_ops.md` §2 and changes only through `core/*.md`.
- **Access control is part of the core**: the layered model (tenant → subject/groups → resource `access_level`/ACL → `PolicyEvaluator` → enforcement app-filter + RLS + citation re-check) is defined in `storage_schema.md` §2.3-§2.4/§4, `modules_spec.md` (`AccessDecision`/`BasePolicyEvaluator`), `architecture.md` §2 and `admin_panel.md` §5A; the security contract tests are `eval_and_ops.md` §1.3. The enterprise layer is gated by the license flags `enterprise_acl`/`collections`/`sso_oidc`.
- **Change procedure**: any architectural change, adding tables/fields to the DB or changing interfaces is first documented in the core files `core/*.md`, goes through review, and only after that is implemented in the codebase.
- **Relation to the project**: the root overview document of the project is at [`../README.md`](../README.md).
